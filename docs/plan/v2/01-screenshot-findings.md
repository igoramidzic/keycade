## What the reference does and does not establish

- The borrower has no top-level application tabs. The lender does. Tabs inside the lender document modal are a separate navigation level and remain appropriate.
- 4776–4783 show lender application detail, not the many-application pipeline. Preserve the existing queue's search, filters, pagination and scoped counts; the user's narrative confirms its role without specifying a redesign.
- The lender application tabs visibly include Overview, Documents, Records, Logs, Portal, Fraud, Notes and Review Changes. Preserve Keycade's functioning lender tabs and add the relevant capabilities to their existing destinations. Do not add empty duplicate tabs merely to copy labels. “Records” informs financial-record access; “Logs” maps to Activity; “Fraud” maps to existing simulated Checks; “Notes” maps to Internal notes. Portal impersonation and a new change-review subsystem are not requested.
- Completed, waiting-for-lender-review and incomplete items coexist. Uploading three documents is distinct from accepting three current evidence items. The duplicate “Initial Application Form” labels in 4775 are not a request to create duplicate requirements.
- The reference advertises more upload formats and 50 MB files. This request does not change Keycade's normal PDF/JPEG/PNG, 25 MiB/file, 10-file batch contract. Text is added to the separate demo importer, which produces a supported synthetic document.
- The red header is a reliable way to distinguish borrower images; it is not a request for a branding clone. Keep the existing default shadcn/Tailwind treatment and match structure and behavior.
- Screenshot controls such as DocuSign, delete/scissors, comments, fraud tabs, Add Process, Organize, stage dropdowns and “Run analysis” do not authorize real integrations, destructive document editing, a workflow designer or unrestricted state changes. Use existing simulated signing, authorized retries, immutable versions and guarded lifecycle commands.
- Visible SAM.gov, OFAC, criminal background, credit pull, KYB vendor, NAICS block-list and DSCR minimum labels do not establish new mandatory checks, provider integrations, scores or eligibility thresholds. Reuse existing configured simulations; only Loan Footprint is a specifically requested new check view.
- Loan Booked is representable as the already-created simulated funded account. No balances, payment schedules, interest or collections are added.

## Resolved implementation assumptions

“Their legal name” means the business legal name on the business-details screen. Personal legal-name collection remains in the existing permitted personal-information task. “Taxpayer identification number” means an optional business EIN in this US demo; do not request a personal SSN during setup. “NAICS score” means NAICS code and industry label, using the existing searchable versioned catalog. These are explicit planning interpretations, not facts proved by the images.

The user asks to mock extraction and analysis and use filenames when text files are dropped into the demo section. The bounded implementation is a demo-panel recipe importer followed by ordinary protected synthetic-document upload, not an OCR engine. Filename selection is intentional within that importer. The [simulation contract](03-data-and-simulation.md#demo-text-import-and-fixture-contract) defines exactly where it applies.

Reviewed financial-record adoption is an implementation choice that fulfills the requested system-of-record updates while preserving Keycade's existing rule that machine suggestions cannot silently become confirmed facts. Source documents and analysis stay immutable; selected accepted values are versioned separately.
