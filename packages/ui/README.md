# Shared UI and the Keycade design system

The three React applications consume this package's TypeScript source and shared Tailwind CSS.
React and React DOM are peer dependencies so the apps own their runtime; the shared Vite
configuration deduplicates both packages.

## Design system

Keycade uses shadcn/ui components (generated by the shadcn CLI) as its primitive layer and a
Keycade theme on top of them. The October 8, 2026 redesign replaced the CLI's neutral defaults
with the tokens below so the bank site, borrower portal and bank console read as one product.
See [the decision record](../../docs/plan/06-decisions-and-sources.md#design-system-redesign--october-8-2026).

### Tokens (`src/styles/globals.css`)

| Token | Use |
| --- | --- |
| `canvas` | Page background behind cards (`bg-canvas`). Application roots use it; cards stay white. |
| `card`, `border`, `input` | Surfaces, hairline borders and form-field borders. |
| `primary` / `brand` / `brand-strong` / `brand-soft` | Deep sapphire. `primary` fills primary buttons; `brand` is for links, current-step accents and icons; `brand-soft` tints selected or current items. |
| `success`, `warning`, `danger`, `info` (+ `-soft`) | Status tones. Pair the strong color (text/icon) with its soft fill. Every pairing meets WCAG AA. |
| `muted`, `muted-foreground` | Quiet fills and secondary text. |
| `demo`, `demo-foreground`, `demo-muted`, `demo-border` | Demo tooling (Scenario kit) only — keeps simulation controls visibly separate from the product. |
| `shadow-xs` … `shadow-lg` | Soft ink-tinted elevation. Cards use `shadow-xs`; dialogs and the sign-in card use `shadow-md`/`shadow-lg`. |

Typography uses Geist. `text-sm` is 16px (regular compact copy) and `text-xs` is 14px (secondary
copy and small buttons); never go below 14px for meaningful text. Page titles are
`text-[1.75rem] sm:text-[2rem] font-semibold tracking-tight`; section titles `text-lg font-semibold`;
card titles `text-base font-semibold`. Use `tabular-nums` for money and counts.

Spacing follows a 4px grid: `space-y-6`/`gap-6` between page sections, card padding 24px
(`Card` default) or 16–20px for dense rows, and 12–16px between related controls.

### Composed primitives

| Component | Purpose |
| --- | --- |
| `app-shell` | `AppHeader` (brand + account slot), `HeaderPortal`, `AppFooter`, `IdentityAvatar`, `shellWidth`. Signed-in workspaces portal their account controls into the header. |
| `brand` | `BrandMark` (keystone arch) and `BrandLockup` (mark + wordmark; the wordmark is the accessible name). |
| `page-header` | `PageHeader` (eyebrow, title, description, actions), `SectionHeading`, `backLinkClassName`. |
| `status-pill` | `StatusPill` (toned badge with dot or icon), `StatusText` (wrapping dot + label for tables), `applicationStatusTone`. |
| `description-list` | `DescriptionList` / `DescriptionItem` for label–value facts. Labels are 14px muted, values 16px. |
| `empty-state` | `EmptyState` for empty lists and `LoadingState` (spinner + `role="status"` text). |
| `textarea` | `Textarea` and `textareaClassName` for legacy plain `<textarea>` fields. |

`Badge` variants include `success`, `warning`, `info` and `brand` in addition to the shadcn
variants. `Alert` adds `info`, `success` and `warning`. Place a lucide icon as the alert's first
child to get the icon column.

### Patterns

- **One primary action per view.** Use the default button for it; secondary actions are `outline`,
  tertiary actions `ghost` or `link`. Link-styled buttons can use `buttonVariants()` — it merges
  conflicting Tailwind classes, so size/whitespace overrides are reliable.
- **Status never relies on color alone.** Always render the status text; tone, dot and icon only
  reinforce it.
- **Rows over walls of text.** Lists of tasks, requirements, documents and checks use bordered,
  rounded rows (`rounded-lg border` or `rounded-xl border`) with a toned icon at the start, the
  title and a one-line status beneath it, and the badge/action at the end.
- **Disclosures** use native `<details>`/`<summary>` with the `disclosure` utility (hides the
  default marker) and a rotating `ChevronDown` with `group-open/<name>:rotate-180`. Keep the
  summary's text content stable — tests and assistive technology read it.
- **Progress visuals** on the borrower list and dashboard are decorative `aria-hidden` bars next to
  the exact count text. Do not add `role="progressbar"` there; native `<progress>` is reserved for
  real in-flight progress (setup wizard, uploads).
- **Dense data** (lender queue) uses a list of `article` rows laid out as a grid with a shared
  column template and an `aria-hidden` header row; each cell keeps a visible label when stacked on
  small screens.
- **Demo tooling** stays visually distinct (`demo` tokens) and must never look like a product
  control.

### Changing UI safely

Browser tests address controls by role, accessible name and exact text. When restyling, keep
visible copy, labels, landmark/region names, heading levels used as names, `aria-*`
relationships and list/region nesting unless the change is deliberate — and then update the
affected `tests/e2e` specs in the same change.

## shadcn provenance

Initialized on October 6, 2026 with `npx --yes shadcn@latest` (resolved version `4.21.3`):

```sh
npx --yes shadcn@latest init --cwd apps/bank-site --defaults --template vite --force --no-reinstall
npx --yes shadcn@latest add button badge card --cwd apps/bank-site --yes
```

The CLI's `base-nova` preset supplied the initial component code. The app's aliases were then
configured for the [supported monorepo workflow](https://ui.shadcn.com/docs/monorepo), and `add`
generated components directly in this package. Separator, Progress, Skeleton, Avatar, Table and
Label were added with the same CLI on October 8, 2026 for the design-system redesign. CLI
dependencies are pinned in this package. Biome formats generated source; component sizing and the
theme follow the Keycade design system above.

To add another used component, run the requested CLI from an app:

```sh
npx shadcn@latest add <component> --cwd apps/bank-site
```

Keep matching style, icon library, and base color in each `components.json`. Run `pnpm
install` to reconcile the single workspace lockfile after dependency changes.
